    这一预设在调什么

    对接格式 motionlab-0.1

    MotionLab 和 Claw 只认这份 JSON，谁都不重新猜那句话是什么意思。参数一改，这里实时更新；导出存档后，就是渲染端的唯一依据，AI 不能再偷偷改它。反过来，把一份旧 JSON 粘回来，舞台会恢复当时的参数。

    rig

    骨架：节点名 + 每段骨头的固定长度。Claw 侧把自己的关键节点一一映射过来，段长在两边都锁死。

    tracks（逐帧关节）

    主角与对手的全部 15 个节点按 60fps 逐帧导出，坐标为舞台 px（0.1 精度），顺序见 rig.nodes。Claw 播放这份轨迹不需要再实现预设逻辑；params 只用于在工具里调手感，不用于回放。根节点轨迹仍按旧格式保留，供旧读取方兼容。

    events

    语义事件带帧号：蓄力开始、离地/起跳、命中、落地、停顿起止、收势开始。阶段起点事件保留原类型（类型即阶段名）以兼容旧版。口播、镜头跟随和音效都挂在事件上，不挂在帧号上。

    checks

    导出时的完整校验快照，与界面用同一套计算：主角+对手的段长（左右两侧+头）、脚滑（对手只计打击前，击退后位移单独记）、出画、重心范围、打击帧对齐、蓄力/停顿/后摇，并给出 pass。渲染完回填一遍，就能对账预演有没有被执行。

    MotionSpec · 导演稿 + 动作库

    这是前半部分的核心：AI 或人只写 Spec——预设、参数、意图、改动理由、假设、标签。工具把 Spec 编译成上面的 motionlab-0.1，Claw 只读编译结果，不读 Spec，也不重新猜句子。Spec 里没有逐帧关节角度，角度是求解器从参数算出来的，所以 Spec 能 diff、能复用、能进库。Spec 是快照，不是实时同步：改了滑杆后，点“生成当前 Spec”再保存。

    motionspec-0.1 字段

    version、preset、params、intent（原文意图）、changes（每处改动：参数、改前、改后、理由）、assumptions（没说清就按默认算的假设，待拍板）、tags、source（sentence / manual / library / seed）。未知参数只警告不拒绝，以便以后扩字段；缺失参数用默认值补齐并警告。

    编译路径

    Spec → 校验（版本、预设、参数范围）→ 应用到舞台（切换预设、按范围 clamp 参数）→ 求解器 pose(t) → motionlab-0.1 逐帧 JSON。AI 在 Muse 对话里也可以直接给你一份这样的 Spec，粘到上面文本框，点“从 Spec 导入”，不用经过一句话解析。

    动作库

    保存在本机浏览器 localStorage，不走服务器。种子库有 3 条：跳蚤起跳、重拳、二连斩。搜名称、标签或意图就能复用；载入后舞台立刻按该 Spec 重算，导出 motionlab-0.1 时就是那一版。

    动作库 · 可复用的导演稿

    场景 · 把几个动作连成一段

    单个动作是词，场景才是句子。原版跳蚤的 5.5 秒也不是一个动作，而是一段建立—打破—跟随—恢复。场景就是把动作库里的 Spec 按顺序排好，段与段之间用一段插值过渡连起来（默认 0.3s），播放时舞台按场景时间走，不用你手动切预设。场景本身也是一份 JSON（motionscene-0.1），Claw 以后可以按段依次播放编译好的 motionlab-0.1，也可以把过渡换成自己的插值。

    过渡是怎么算的

    过渡段内，主角（以及两边都有对手时对手、两边都有剑时剑）的每个节点坐标按 smoothstep 在前一段末帧和后一段首帧之间插值，根节点、剑尖同理。过渡不是硬切，也不是在原预设里加一帧；它是场景层加的，不是动作本身的帧。段内时间仍按各自 Spec 的 timeline 走。

    场景与单动作的关系

    场景里每一段都是一份完整的 MotionSpec，改库里的 Spec 不会自动改场景里的那一段——场景存的是那一刻的快照，锁定才有意义。想改场景里某一段，先在库里改好，再重新加入场景。

    跨域接口 · 换约束，不换引擎

    时间线、事件、校验这套语言不变，换的是求解器：生物力学看关节角和重心支撑，机械看行程和啮合，天文看能量和角动量。每个域都有自己的画布、参数、校验和导出（domain-*.1），不混进 motionlab-0.1，不碰 Claw。

    生物力学 · 步态（双连杆腿 + 逆运动学）

    骨盆和脚是目标，膝盖由两段腿长（各 50px）用余弦定理解出来，不是画出来的。校验：膝屈曲角、重心是否在支撑面内、摆动脚离地间隙。

    机械 · 曲柄滑块 + 齿轮

    曲柄转一圈，活塞走一个来回；齿轮转角是曲柄转角除以齿数比、方向相反。校验：连杆必须长于曲柄、活塞行程 = 2×曲柄半径、齿轮比。

    天文 · 开普勒轨道 + 近地点点火

    轨道不是画出来的椭圆，是开普勒方程牛顿迭代解出来的位置；近地点给一个切向速度增量，变轨后的新轨道由活力公式和角动量算出来，不是手画的。校验：每段内能量和角动量守恒、周期符合开普勒第三定律。

    先把三个问题说清楚

    这是你开工前问的三件事。结论都写在工具里了：下面的说法，就是上面这个舞台实际的做法，不是另一套 PPT。

    问题 1

    产品形态与技术路线是什么？

    形态：一个浏览器里打开就能玩的动作预演台。没有安装、没有服务器、没有账号 —— 和 Still / Life 的单页 index.html 是同一种东西。

    路线：数据驱动，不是 AI 直接画画。

    • 引擎层 —— Canvas 2D + 确定性 pose(t)：给第几秒，算出每个关节在哪。能定格、能逐帧、能反复看同一帧。
    • 数据层 —— 动作 = 一份 JSON：骨架、时间线、事件。不存视频，不存代码。
    • 校验层 —— 引擎顺带当裁判：段长、脚滑、重心、出画，犯规当场报。

    不重复造轮子：不做物理引擎、不做 3D、不做动捕。Blender / Cascadeur 那套重型预演和你的二维水彩管线不合，这里只补你管线里缺的那一层。

    问题 2

    到底可不可行？

    可行，高可行 —— 前提是守住范围。

    • 容易：火柴人、拖时间轴、慢放逐帧、预设、导出 JSON。Still / Life 已经证明浏览器里能跑确定性骨架。
    • 中等：一句话出草稿、双人对打、命中停顿、镜头跟随。难在手感参数要调准，不在原理。
    • 先不做：真实生物力学仿真、三维、AI 直接生成视频。原版跳蚤本身也是纸偶的艺术改编，不是解剖仿真 —— MotionLab 要的是「带生物力学味道的约束」：蓄力、下沉、蹬地、收腿、缓冲、触地。

    一条边界：火柴人通过 ≠ 成片通过。它查不了水彩质感和服装贴合（cosplay 那轮高位头饰悬浮就是例子）。目标是「动作不再返工」，不是「成片不再检查」。

    问题 3

    怎样和 AI 配合？

    分工只有一句话：你当导演，AI 当翻译，工具当裁判，三者不串位。

    • 你只说意图、判手感：「这拳不够重」「落地太飘」。手感只有你能拍板。
    • AI 把句子翻译成时间线草稿，并用人话解释参数。你说「不够重」，它只改数 —— 拉长蓄力、加命中停顿、加重落地缓冲 —— 不重画一遍。
    • 工具负责画出来、报犯规、锁定版本。你点头的那一版导出存档，谁都不许再改。

    上面的一句话输入框就是这个配合的最小形态：句子 → MotionSpec 导演稿 → motionlab-0.1 编译结果，每处改动都写明改了什么、为什么。

    复刻一场游戏战斗，在这里具体怎么干

    ① 拆帧

    把原战斗按 60 fps 拆开：前摇几帧、判定在哪一帧、命中停几帧、后摇多久、对方退多远。上面的帧数据面板就是拆完的样子。

    ② 对齐

    0.25× 慢放 + 逐帧步进 + 残影轨迹，先把打击帧和对方受击帧对齐，再谈像不像。距离标尺在地面上，退多远看得见。

    ③ 调手感

    「重」不是形容词，是三个数：蓄力更长、命中停顿更多帧、恢复更慢。一次只改一个数，改完立刻重播对比。

    ④ 锁定

    调到接近就导出 JSON 存档。这一版就是「这场战斗」的定稿；以后交给 Claw 渲染，渲染端只执行，不再 reinterpret。
